# 架构

## 目标

SelfIndex 当前的目标是：

- 尽可能忠实地保存个人原始资料
- 构建轻量但持久的可搜索记忆层
- 支持变化的来源而不丢失历史状态
- 保持本地优先和可维护性

## 三层架构

### 1. 归档层

职责：

- 存储原始资料
- 存储当前文档状态
- 存储修订历史
- 处理创建、复制、更新和非活跃转换

当前实现：

- `raw_documents`
- `raw_document_revisions`

### 2. 记忆层

职责：

- 从当前修订版派生适合检索的单元
- 存储分块内容和摘要
- 存储 recall-domain 标签
- 为嵌入工作流提供稳定输入

当前实现：

- `memory_units`
- `Chroma` 集合

### 3. 召回层

职责：

- 解析查询
- 按向量相似性检索
- 按 recall domain 过滤
- 默认忽略非活跃源文档
- 将命中文档追溯到原始文档

当前实现：

- `engine/query_syntax.py`
- `engine/retriever.py`
- `/api/memory/search`

## 为什么存在修订版

SelfIndex 不再是一个一次性导入工具。

它已经需要支持：

- 随时间变化的 Markdown 笔记
- 导出的对话
- 可能增量增长的浏览器捕获对话
- 在多次同步中逐渐完整的懒加载来源

没有修订版，后来的导入将直接覆盖之前的状态。

## 为什么记忆单元仍然重要

`memory_units` 不是归档。

它们是记忆表示层，负责：

- 适合搜索的分块
- 摘要存储
- recall-domain 标签
- 嵌入状态

归档保存来源真相。记忆层保存检索可用性。

## 为什么浏览器捕获适合这个架构

浏览器捕获不是独立的存储模型。

它是另一种摄入路径，最终仍落入相同的归档和记忆结构：

- 源页面 -> 规范化的浏览器载荷
- 浏览器载荷 -> `raw_documents`
- `raw_documents` -> `raw_document_revisions`
- 当前修订版 -> `memory_units`

对于 Grok 等懒加载来源，SelfIndex 现在支持合并步骤，使用重叠的 message id 作为锚点，并在不重写内容或嵌入的情况下重新排序 `sequence`。

## 刻意不做的目标

在这个阶段，SelfIndex 有意不尝试成为：

- 知识图谱平台
- 多用户 SaaS 系统
- 个性化驱动的 Agent 产品
- 全面的浏览器自动化系统

该项目仍在优化本地优先的记忆管道，而非广泛的产品层。
