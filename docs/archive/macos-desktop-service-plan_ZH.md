# macOS 桌面 App 与本机服务实施计划

> 2026-09-27 归档。保留原始决策和实施记录；现行入口与待办见 `docs/README_ZH.md` 和 `docs/audit-2026-09-26/07-backlog-and-handoff_ZH.md`。

## 目标与边界

- 用户点击 `SelfIndex.app` 打开独立窗口，在 Dock 中切回；界面不依赖浏览器页面。
- 后台服务独立于窗口运行，供桌面 App、浏览器扩展和其他本机 App 调用。
- 第一阶段只支持同一台 Mac 上的客户端，API 绑定 loopback；跨设备访问另行设计。
- 沿用现有 SQLite/SQLCipher、Chroma、embedding、导入和检索逻辑。
- 初版桌面功能覆盖搜索、结果列表、原文详情、编辑和服务状态。导入管理与高级维护功能随后补齐。
- 关闭窗口后服务继续运行；“退出 SelfIndex”明确结束桌面进程。是否停止服务由单独控制项决定。

## 建议结构

```text
PySide6 桌面 App ──┐
其他本机 App ───────┼── 本机 JSON API ── 业务逻辑 ── SQLite / Chroma / 模型
浏览器扩展 ─────────┘
                         ↑
                  launchd 管理服务进程
```

服务进程是数据库与向量库的主要写入者。桌面 App 只通过稳定接口访问数据，避免 UI 与服务各自打开数据库进行并发写入。现有 Flask 页面可在过渡期保留，但不作为桌面界面的实现基础。

## 阶段 0：基线与数据保护

- 记录 macOS/Python 架构、依赖版本、现有数据目录和测试结果；确认模型离线缓存可用。
- 为数据库和 Chroma 建立一致的备份与恢复流程，迁移前保留原始 `data/`。
- 明确当前 Windows 路径记录的处理方式；批量改动用户数据前单独核对新旧路径映射。

验收：基线测试通过；从备份可恢复检索；数据迁移方案不覆盖唯一副本。

## 阶段 1：稳定本机 API

- 在现有 `/api/memory/search`、`/api/memory/<id>` 之上定义版本化 JSON 契约，包括查询参数、结果字段、错误结构和状态码。
- 增加健康检查、JSON 编辑保存；桌面首版需要的筛选、排序和导入状态按实际交互补齐。
- 把编辑/导入业务逻辑从 Flask HTML 路由中抽离，让 JSON 与旧页面共用同一实现。
- 服务固定绑定 loopback；写操作使用本机令牌，限制请求大小和来源。浏览器扩展同步更新调用方式。
- 补 API 契约测试与数据库/向量更新失败时的一致性测试。

验收：桌面首版所需流程均可只用 JSON 完成；旧导入和检索行为仍通过测试；未经授权的写请求失败。

## 阶段 2：服务生命周期与数据位置

- 用用户级 LaunchAgent 管理后台服务的启动、重启与停止；开发脚本继续可用，但不与 `launchd` 同时管理同一进程。
- 将独立 App 的可写数据和日志放到用户目录；模型缓存位置固定，保留环境变量覆盖能力。
- 设计从项目 `data/` 到 App 数据目录的显式迁移：先备份、再复制验证、最后切换；失败可回退。
- 增加单实例、端口占用识别、启动超时和有界日志。

验收：登录后按设置启动服务；关闭桌面窗口不影响外部 API；服务崩溃后的恢复符合设定；重启和迁移后原有数据仍能检索。

## 阶段 3：PySide6 桌面界面

- 新建 macOS 桌面入口，不复用 Windows 专属的 `desktop/tray.py`。
- 实现搜索、结果列表、原文详情、编辑、服务状态、错误与加载状态。
- 耗时检索、导入和模型加载放在工作线程，不阻塞窗口；支持 Dock 再次点击时唤起已有窗口。
- 先完成 Dock 常驻；菜单栏图标作为第二步加入，避免首版同时维护两种入口。

验收：从桌面入口完成搜索、查看和编辑；窗口关闭/重开、服务不可用、重复启动都有明确表现；界面不打开浏览器。

## 阶段 4：打包与日常运行

- 打包为可点击的 `.app`，处理 Qt、Torch、SQLCipher、Chroma 和模型资源的定位。
- 在干净的 macOS 用户账户验证安装、启动、登录后服务、升级和卸载；用户数据不放在 `.app` 内。
- 自用版本先验证本机安装；对外分发时再加入签名、公证和安装包流程。

验收：无需项目源码目录或手工激活 `.venv`，双击即可使用；另一款本机 App 可调用 API 并获得稳定 JSON 回复。

## 工作分配与质量门槛

- 主代理负责接口与进程边界、数据迁移决策、集成、测试及最终验收。
- Luna 负责边界明确且互不覆盖的子任务，例如 API 契约测试、独立桌面组件、打包配置审计和文档。
- 同一文件只安排一个写入者；每个子任务交付改动文件、验证命令和未解决问题。
- 每阶段通过验收后再进入下一阶段。并行代理可能增加总 token 用量，试运行时记录返工量与实际成本，再决定是否扩大使用。
