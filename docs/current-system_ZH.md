# 当前系统

本文档回答一个简单的问题：

SelfIndex 现在是什么，还不是什么。

## 当前定义

SelfIndex 不再只是一个重命名的聊天记录搜索工具。

在这个阶段，它是一个个人记忆系统原型，具有以下活跃边界：

- 归档：保存原始资料和当前文档状态
- 修订历史：为变化的来源保留快照
- 记忆：从当前修订版派生适合检索的记忆单元
- 检索：向量搜索，可追溯到源文档
- 保护：受保护的召回域，带有显式解锁风格查询

## 核心数据流

### 导入时

```text
源数据
-> 规范化为 raw_document
-> Upsert 当前 raw_document
-> 当内容变化时创建或更新 raw_document_revision
-> 从当前修订版构建 memory_units
-> 可选地将向量写入 Chroma
```

### 检索时

```text
查询
-> 对查询进行嵌入
-> Chroma 返回候选 memory_units
-> SQLite 批量加载详情行
-> 按 recall_domain 和活跃状态过滤
-> 返回结果及追溯载荷
```

### Markdown 同步时

```text
扫描目录
-> 应用忽略规则
-> 使用相对路径作为 external_id
-> 通过内容哈希检测创建 / 跳过 / 更新
-> 将缺失文件标记为非活跃，并追加已删除修订版
```

### 浏览器捕获时

```text
AI 网页
-> 捕获可见的对话快照
-> 将消息规范化为浏览器载荷
-> 导入到 raw_documents / memory_units
-> 可选地与现有对话锚点合并序列
```

## 已确立的设计原则

### 1. 当前状态和历史是分开的

- `raw_documents` 存储当前状态
- `raw_document_revisions` 存储历史

这允许 Markdown 笔记、导出的对话和浏览器捕获的对话共享一个存储模型。

### 2. 记忆单元绑定到修订版

`memory_units` 附加到 `revision_id`，而不仅仅是 `raw_document_id`。

这意味着：

- 记忆可以追溯到特定版本
- 更新的文档可以生成新的记忆单元
- 旧版本不需要被覆盖

### 3. 保护规则和保护结果是分开的

- `protected_terms` 存储规则
- `memory_units.recall_domain` 存储结果标签

这保持检索快速，因为整个数据库不需要在查询时重新判断。

### 4. 非活跃不等于删除

对于可变来源（如 Markdown 同步）：

- 缺失的文件不会从历史中物理删除
- 当前状态标记为 `is_active = 0`
- 默认检索忽略非活跃项
- 历史修订版仍然可用

## 已经正常工作的功能

- 导入和同步内容的修订感知存储
- 独立的嵌入工作流
- 带忽略规则和删除检测的 Markdown 目录同步
- ChatGPT 导出导入
- ChatGPT 浏览器同步
- Grok 浏览器同步与懒加载合并行为
- 受保护的召回域
- SQLite / SQLCipher 存储

## 仍在完善中的功能

- 尚无完善的修订浏览器 UI
- 尚无完成的对话回放 UI
- 浏览器捕获仍依赖特定网站的 DOM 结构
- 浏览器支持仍在早期阶段，按提供商定制
- 桌面运行时仍是 Windows 优先
